# 07 – Anforderungen aus Befunden im Altsystem

Bei der Analyse des SAP-GUI-Monitors (Oktober 2026) gefundene Schwachstellen. Die Neuentwicklung darf sie **nicht** übernehmen. „Belegt“ = im Code nachgewiesen; „zu prüfen“ = Hypothese, vor Umsetzung verifizieren. „Schicht“ = wo die Anforderung in der Zielarchitektur umgesetzt wird (E-15: Schrittlogik, Eingang und Notifications laufen in CAP; S/4 nur noch über `API_BUSINESS_PARTNER`).

| ID | Befund im Altsystem | Anforderung an die Neuentwicklung | Schicht | Status Befund |
|---|---|---|---|---|
| R-01 | Schritte laufen ohne Sperre (Monitor öffnet im Anzeigemodus, `execute_function` prüft keine Sperre) → zwei Benutzer können parallel CREATE ausführen (doppelter BP/Debitor). | Schrittaktion nur mit gültigem ETag; CAP serialisiert pro Vorgang (Zeilensperre in der Transaktion). | CAP | belegt |
| R-02 | CNG_NEW wandelt CH_DEB (nie freigabepflichtig) in CR_DEB um, ohne die Freigabe neu zu prüfen → Neukundenanlage ohne Freigabe in 7020/7050/7080/7110 bzw. > 5.000 EUR in 0001. | Bei Prozessartwechsel Freigabeprüfung erneut ausführen. | CAP (im Mock umgesetzt) | belegt |
| R-03 | Notification aus BAdI `CUSTOMER_EXTENSION_CHECK` in der Prüfphase per `STARTING NEW TASK` → Magento kann vor dem Commit lesen; Mehrfach-Notifications. | Notifications erst nach Commit, genau einmal (CAP-Outbox, E-17). | CAP | belegt (Timing), Auswirkung zu prüfen |
